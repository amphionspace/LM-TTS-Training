# 用音素识别核查 TTS 读音（调研记录，2026-10-22）

状态：**仅记录，未实现。** 当前优先级仍是监督 langid run 和 CV3 评测。

来源：[用 Kaldi 音素识别验证 TTS 发音](https://quaily.com/goldengrape/p/using-kaldi-phoneme-recognition-validate-tts-pronunciation)。

## 问题：CER 看不到多音字读错

Seed-TTS / CV3 的 zh CER 由 Paraformer 转写后按字比对。ASR 自带语言模型，
音频把“攒竹”读成 zǎn zhú 时，转写多半仍是“攒竹”，CER 记为正确。
因此多音字、声调错误基本不进入 CER。

我们的模型直接读 Qwen BPE 文本，没有 G2P 或拼音输入，多音字只能靠训练数据隐式学到，
这类错误在现有指标里是盲区。

## 原文方法

1. Kaldi + Vosk 中文模型 `vosk-model-cn-0.22`，音频转 16 kHz 单声道。
2. 每个待查字配两条 TTS 音频：
   - **测试句**：含待查字，例如“攒竹穴在眉头内侧，按压攒竹穴可以缓解头痛。”
   - **标定句**：用读音明确的字覆盖各候选读音的音素，例如
     “全体村民，咱们侧身团坐，敢说敢做，泉水长流。”（村/侧→c，咱→z，敢→an3，全/团→uan2）
3. 解码后不看词序列，只看音素序列；词级结果会被语言模型“纠正”。
4. 模型包没有音素名表，输出只是编号。用标定句反查编号含义，并按模型的分组规则合并词首/词尾等位置变体。
   编号只对这个模型有效。
5. 判定：两处“攒”都是 `631 77` = z + an3，即 zǎn（正确应为 c + 介音 + an2）。
6. 再看 top-10 候选路径，没有出现 cuán 的结构才判错；证据含糊、模型分不开的读音（如“穴/血”）不下结论。

## 评估

有用的部分：

- 核心观点成立：检查读音要看音素层，不能看 ASR 文字。
- “证据不足不判”的边界是对的，适合做精确率高、覆盖率低的检查。

不适合直接照搬的部分：

- 用标定句反查数字编号，是手工、按模型、按字做的，不能批量跑。
- 用 1-best 加 top-10 路径判断，是间接证据；Kaldi chain 模型对声调的区分本身不算强。
- 只能查事先指定的字，给不出整个测试集的指标。

## 如果要做，建议的做法

把“看解码路径”改成**候选读音强制对齐比分**：

1. 建一个多音字测试集：每条文本标注目标字及其正确读音、常见错读，例如 攒 cuán / zǎn、
   行 xíng / háng、重 zhòng / chóng。可从多音字词典和 Seed zh / CV3 zh 文本中挑。
2. 对每条 TTS 输出，用带拼音（含声调）词典的声学模型，分别按“正确读音”和“错读”两条拼音序列做强制对齐，
   比较目标字片段的对数似然或 GOP（goodness of pronunciation）。
3. 似然差超过阈值才判对或判错，否则记为“无法判定”。阈值在真人录音或人工核对的样本上标定。
4. 输出整体指标：多音字正确率（只算可判定样本）和可判定率。

这样不依赖数字编号，可以批量跑，也能按 checkpoint 跟踪。
声学模型可以换成输出拼音或音素的 CTC 模型，同样是比较两条候选序列的 CTC 概率。
