# 2026-10-01：16 数据集 FP32 全量训练

## 数据与配置

- Selection：`tts-selection-supervised-tts-20260929T151539bjt-01`。
- 数据：2026-10-01 发布的 16 个 merged features 表，共 128,220,178 条；每张表包含 codec、speaker embedding、text，并固定各自的来源与提取版本。
- 实验：`configs/supervised-tts-20260929-all16-fp32-32gpu-lr3e-4-bblr1e-4-ep3-wsd.yaml`。

- 数据索引：`data/builds/supervised-tts-20260929-merged-20261001-all16/`。约 0.1% 按数据集固定抽样验证，seed 42；样本行隔离，不保证说话人 / 文本隔离。

## 优化器与计划

使用 4 节点 × 8 张 A800，FP32 / SDPA、FSDP2、token loss，residual 权重 0.3，完整训练 3 个 epoch。模型在本地提前组装，训练作业仅加载已完成产物。

历史记录中新增模块 / backbone 的峰值 LR 为 `3e-4 / 1e-4`，本次保持这组值，不随卡数线性放大。历史 warmup 步数不适合直接复用：本次 WSD 根据已消费样本占总 3 epoch 的比例调度，前 1%（0.03 epoch）线性 warmup，随后 steady，到 2.7 epoch 开始余弦 decay，结束时为峰值的 10%。两组 LR 使用同一倍率。

正式 batch 预算需结合完整模型的显存与吞吐实测选择。FP32 限制每卡 codec frames、有效 token 总数以及 padding 后 token 数；随机窗口内做长度分桶。不会为了填满显存而放弃长样本余量。

## 启动前验证

- merged 表来源固定、一次读取三个特征；源文件不改写。
- 单条损坏 feature 隔离；分布式空 microbatch 同步跳过，loss 按剩余有效 token 归一化。
- 双卡 FP32、3 epoch、WSD、固定验证集、注入坏 codec，以及中断恢复均经过真实训练验证；连续与恢复权重逐位一致。
- 本地四卡完整模型预算比较：3000 frames / 8000 tokens 的中位音频吞吐约 163 秒/秒；6000 / 12000 配合长度分桶约 302 秒/秒。它们是短时单机测量，不代表跨节点完整语料吞吐。
- 12000 / 20000 在分桶交界暴露了 padding 显存突增，随后增加 FP32 的 padded token 预算；修复后的测试和跨节点结果以实际运行记录为准。

最初每数据集随机抽 128 条估算总音频约 36.2 万小时。按四卡 302 音频秒/秒理想线性扩展，3 epoch 约 19 天；这不是承诺，尚未计入跨节点通信、数据长度差异、保存和全量验证。全量索引完成后用真实总时长和 32 卡稳定吞吐更新估计。

所有预算测试的配置与日志归档到 run 的 `preflight/`。正式启动后，作业 ID、有效配置、代码快照在 `submissions/`，checkpoint、TensorBoard、节点日志和 GPU 采样各自存放，不与模型资源混放。

## 全量数据与 32 卡预检结果
