# 10kh 训练故障处置

适用于用户授权的 `runs/emilia-en-zh-dynamic-10000h` 正式训练。总目标是两个 epoch；不得为让任务继续而静默缩短训练、跳过坏数据或绕过恢复检查。主会话观察前 2,000 步期间，由主会话执行干预，巡检 session 只记录与建议。之后按本表自主处理证据明确、可验证的故障。

## 共同步骤

1. 保存 UTC 时间、最近成功 step、完整报错、进程身份、GPU/CPU/I/O/磁盘、最近完整 checkpoint 及正在进行的训练/保存/评估阶段；在巡检文档追加证据。
2. 判断是预期工作、瞬时外部故障还是持续故障。一次 loss 波动、一个慢 step、评估期间训练 step 不动，均不足以中断训练。
3. 必须停止时，先核对 PID、`start_ticks` 和命令，再只终止本 run 的进程组；先 TERM，确认无法退出后才 KILL。保留退出前日志，检查所有 rank 是否退出。不要碰其他任务。
4. 每次只实施有证据支持的必要修复，记录修改前后值、原因及验证。恢复使用本 run 的 `launch.py` 和最近 `COMPLETE` checkpoint；无完整 checkpoint 时保留现场，记录阻塞，不自动从头重跑。
5. 每项修复后验证：恢复 step/data cursor、优化器和 scheduler 按预期接续；至少再观察 20 次更新（两个日志点），loss/梯度有限、学习率连续、吞吐恢复。涉及生成的修复必须再通过相应模式的真实评估。失败则停止同一路径重试并记录剩余问题。

## 分类型处置

| 问题 | 判断证据 | 首选处置与恢复要求 |
|---|---|---|
| CUDA OOM | traceback 所在训练前反向 / 验证 / 生成 / codec / ASR 阶段，各 rank 峰值与当前显存、同卡其他进程 | 先排查本 run 残留、意外加载和引用未释放；不要杀其他任务。针对实际分配峰值修复。确需降低训练预算或评估 batch 时，先解决下述签名/训练计划约束，再验证压力测试与恢复。禁止无修改循环重启。 |
| NaN / Inf loss 或梯度 | `Non-finite loss` / `Non-finite gradient norm`，首个异常 step 与 batch，之前的 LR/grad_norm | 保留失败 batch 的可重现身份，核查输入 codec/音频是否有限、dtype、loss 归一化及学习率是否符合计划。先修复数据/实现错误；异常发生前 checkpoint 也必须检查是否有限。不得跳过更新掩盖问题、清空优化器或任意降 LR。数据源确实损坏时先核对原始数据和已有哈希，无法恢复同一数据则停止记录。 |
| 训练退出 / rank 掉线 | `training-exit.json` 与当前 PID 匹配，非零退出码，首个 rank traceback 或系统 OOM 证据 | 修复首个根因，其他 rank 的 NCCL 错误可能只是后果。瞬时外部故障已确认消失时，可从完整 checkpoint 尝试一次恢复；同样原因重现则停止盲目重试。 |
| 训练卡死 / NCCL timeout | 两次采样确认训练 step 和评估/保存文件都无进展；结合 GPU 活动、进程状态、I/O、首个 rank 日志 | 先排除正常评估、全量清单加载、epoch 规划和 checkpoint 写入。空闲或阻塞持续时收集进程栈/日志，区分数据 worker 阻塞和 rank 不一致；不要靠无限增加 NCCL timeout 掩盖问题。确认卡死才停止本 run、修复并恢复。 |
| 数据加载 / tar / codec 错误 | 明确样本 ID、源路径、异常、可复现读取，文件大小/哈希与准备报告 | 核查挂载、路径、共享缓存及原始 tar。瞬时读故障消失后恢复；不能删除样本、用零音频替代或重新随机划分验证集。修复 prepared 产物必须证明内容与原输入一致，清单改变不得绕过训练签名。 |
| 吞吐下降 / CPU 内存压力 / worker 退出 | 连续至少 3 个正常训练日志点的 step_seconds/data_wait_seconds 相对稳定阶段明显恶化，并有 CPU/I/O/内存证据 | 排除保存、评估、epoch 边界和 batch 长度差异。CPU/内存过量时降低 workers 或 prefetch；I/O 瓶颈时以实际测量选择并发数。二者不在恢复签名内，但仍需要 checkpoint 恢复及前后吞吐、内存对比；不把增加 worker 当作所有慢问题的解决法。 |
| 磁盘空间不足 / checkpoint 写失败 | 可用空间、实际 checkpoint 大小、写入异常；`latest`、`COMPLETE`、metadata 与分片一致性 | 当剩余空间不足再容纳一次完整 checkpoint 和评估产物时提前干预。保留最近完整恢复点，停止继续制造写失败。不得清理受保护 runs、数据、模型或失败现场；未获清理授权时记录需扩容/释放空间的阻塞。不能把不完整目录当作 checkpoint，也不能手工补 COMPLETE。 |
| checkpoint 恢复失败 | 签名差异、world size、分片缺失、load 异常 | 核对是否选了本 run、同一数据/模型/配置与 4 ranks。若最新 checkpoint 实际损坏，可检查上一份完整 checkpoint，并在确认可加载后记录回退步数及重算范围。不得编辑旧 metadata、跳过签名检查或只加载模型冒充完整恢复。 |
| 生成、codec 或 ASR 失败 | 逐条 metrics、哪个 mode/目标失败、原始报错、生成 WAV 与参考 WAV 是否存在/可读 | 区分生成本身与后处理失败；检查当前依赖、模型缓存、时长/采样率和设备。保留已生成的有效音频；评分故障优先重评分已有音频。修复后实际验证 speaker_only 和 ICL，不将缺失指标记成零，也不自动关掉 ICL 或 ASR。 |
| WER/CER 退化、截断或时长异常 | 连续多个 eval 的同一目标/参考、EN/ZH 分开指标、英语规范化、ASR 原文、目标时长与截断；必要时检查音频 | 先检查参考配对、ICL 前缀裁剪、生成上限和 ASR 是否出错；8 条在线样本不足以下定论。无实现故障且仅短期波动时保持配置，继续观察。持续严重退化需复现、扩大诊断并形成有证据的干预；不要仅凭早期 ICL 较差就改训练目标或学习率。 |
| 巡检 CLI 失败 / 超时 | `supervision/status.json`、该次 `.codex.log`、退出码和时间 | 保存本次失败，保持同一 session ID，下一个周期重试；1500 秒到时终止本次巡检进程组，禁止巡检重叠。训练进程独立运行。若认证/服务不可用，脚本无法替代模型做故障诊断，须明确记录监督中断，不能报告“巡检正常”。 |

## 会改变恢复语义的调整

当前 checkpoint 签名包含动态 batch 预算、学习率与 schedule、模型设置和 eval 配置。用户授权修复不等于允许伪造签名兼容：需要改变这些设置时，先检查代码，设计并验证恢复方法，明确数据游标、batch 重排、优化器状态和剩余两 epoch 的计数。不能验证就保留 checkpoint、停止相应恢复尝试并记录所需后续工作。仅调整 workers/prefetch 不改变组批序列，现有恢复检查允许它们变化。

## 完成判断

正常退出仅是一个条件。还需核查第 38,539 步完整 checkpoint、最终验证 loss、两种模式最终 summary 和冻结权重检查。若训练已完成但评估/校验缺失，应补齐对应评估或校验并记录，不能从头重跑训练。
